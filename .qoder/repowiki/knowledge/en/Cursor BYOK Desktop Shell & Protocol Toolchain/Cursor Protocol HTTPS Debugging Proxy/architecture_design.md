Single Go package `proxydebugger` exposing a `Server` type (proxy.go) that runs two HTTP servers on separate listeners: an `elazarl/goproxy`-based HTTPS proxy on the proxy address and a static-file UI server on the UI address. The proxy uses `cursor/internal/certs` to generate a per-process CA and performs MITM only for the configured `target-host` (`api2.cursor.sh` by default), transparently forwarding all other CONNECT traffic. Capture pipeline: `captureRequest`/`captureResponse` wrap bodies in `captureReadCloser`, dispatching `RunSSE` streams through a 5-byte Connect-frame decoder (`decode.go`) and unary payloads through protobuf unmarshalers keyed by path constants. All captured exchanges live in an in-memory `exchangeStore` (store.go) with a bounded FIFO order, RWMutex protection, and an SSE event channel used by `/api/events`. The embedded frontend (`web/`) is served via `embed.FS` and talks to the store through JSON REST endpoints plus Server-Sent Events. Dependency direction is one-way: proxy → decode/store/types → web assets; no reverse imports.
