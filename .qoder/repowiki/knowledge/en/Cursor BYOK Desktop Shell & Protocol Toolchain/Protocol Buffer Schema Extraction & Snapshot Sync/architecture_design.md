Two-layer design: a Go extraction tool (`ext_tool/`) parses minified JS bundles (via `main.go` CLI + `extractor.go` regex-based AST) to emit `.proto` files, while shell scripts orchestrate the workflow. `extract_extensions_proto.sh` locates a Cursor extension bundle (`cursor-always-local/dist/main.js` or similar), runs the Go extractor with `-skip-format -strict`, and atomically swaps the output directory under `from_extensions/`. The extracted proto pairings (`agent_v1.proto`, `aiserver_v1.proto`) live alongside hand-maintained copies at the repo root; `check_proto_sync.sh` diffs them after normalizing `option go_package` so any drift fails CI. Dependency direction is one-way: scripts → Go extractor → generated `.proto` files consumed by the rest of the codebase via `go_package = "cursor/gen/<pkg>;..."`.
